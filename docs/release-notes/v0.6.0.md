AgentLatch v0.6.0 grows the runtime side: more runtime gates that report findings on recorded MCP traffic, a sealed event store, optional connectors, and a runtime proxy that now records a tamper-evident trace by default. The static scanner's rules are unchanged from v0.5.1.

> **Early proof of concept.** The scanner uses static heuristics, and the runtime side records traffic and reports findings only. Neither is a security guarantee. A clean scan does not mean an agent is safe.

## Behavior change: the runtime proxy records a trace and ledger by default

`agent-latch-runtime proxy` now records a trace and seals it into a tamper-evident ledger without any flags. After upgrading, a proxy started with no `--trace` writes files where it used to write nothing.

- **Where.** Each run gets its own folder, `~/agent-latch/runtime-logs/<server name>/<YYYYMMDD-HHMMSS>/` (UTC), holding `trace.jsonl` and `trace.ledger.jsonl`. The folder does not depend on where an MCP client starts the proxy, and it is outside any project. A run never reuses a folder, so two proxies never share a hash chain. The proxy prints the folder at startup and on exit.
- **Opt-outs.** `--no-ledger` records the trace unsealed. `--no-trace` records nothing. `--log-dir DIR` moves the root. `--trace FILE` and `--ledger FILE` still set exact paths, and a `--trace` alone now also gets `TRACE.ledger.jsonl` beside it. Contradictory flags (`--no-trace` with `--trace` or `--ledger`, `--no-ledger` with `--ledger`) exit `2`.
- **Payloads stay opt-in.** `--record-payloads` (new) writes `payloads.jsonl` into the run folder, so `import-logs --dir` finds it. `--payloads FILE` still sets another path. The file holds masked tool arguments and outputs and is sensitive. Without it, ALR10 has nothing to read.
- **Fails open on defaults only.** If a default location cannot be written, the proxy warns and keeps serving. A path you gave explicitly that cannot be opened still exits `2`.
- **`import-logs --dir` names one run.** Pointing it at a folder of runs (or giving no `--dir` while runs exist in the home folder) lists them and exits `2`. Nothing is guessed. With no `--dir` and no runs, it still reads `./runtime-logs/`, where `demo` and older setups write.
- **The proxy imports its run when it stops.** It runs the same one-shot import as `import-logs --once` over its run folder (`events.csv`, `gate-results.csv`, `gate-results.sarif`) and prints the folder, a findings summary, the ledger verdict and the report and anchor commands. It never changes the exit code (a failure prints a warning with the manual command). `--no-import` turns it off, and `--quiet` imports silently. `import-logs --once` on a folder with no `trace.jsonl` now exits `2` instead of doing nothing.

Existing commands with explicit `--trace`, `--payloads` and `--ledger` paths keep working unchanged.

## New: runtime gates

Runtime gates are monitor-only plugins that run on every recorded event. They report findings and never block. See [docs/GATES.md](../GATES.md) for each gate's detectors and its informational OWASP Agentic and EU AI Act references.

- **ALR03, endpoint trust.** Checks the recorded handshake for a missing server identification, a server whose identity changes, and a server name that impersonates another.
- **ALR04, tool definition injection.** Reworked. Flags instruction-like content in MCP tool definitions, a declared read-only or offline tool whose input schema accepts writes or network destinations (`ALR04-R01`), schemas that accept conversation context or credentials (`ALR04-R02`), and tool names that collide with or resemble another server's tools (`ALR04-R03`).
- **ALR05, tool results.** Reviews instruction-like content in MCP tool results. These are review signals, not verdicts.
- **ALR10, secrets crossing the tool boundary.** Reads masked payloads only, so it never sees or writes a raw secret. An optional operator `--policy` file sets an allowlist.
- **ALR16, package installation integrity.** Looks at the arguments of tool calls for package installs that use a custom source, are unpinned, or arrive through pipe-to-shell, chained commands or write-then-run. Output never contains commands, URLs or package names.

`--policy FILE` is trusted operator configuration and is never read from the monitored project. A runtime report now exports to SARIF 2.1.0 (`gate-results.sarif` is written on every import), and `agent-latch --runtime-result ... --format sarif` exports the ledger verdict (`ALR15-R01`) with the runtime findings.

## New: sealed, append-only event store

`import-logs --database FILE` now seals every stored row into a hash chain, the same idea as the trace ledger, and refuses a store that no longer matches its seals, table layout or anchor (exit `1`). `--anchor PATH` publishes the newest seal. `verify --database FILE` and `agent-latch --runtime-result --database FILE` report the same six verdicts as the trace ledger. A store that does not seal its rows is never accepted silently (`ALR15-R02`). A read-only `audit-tool` MCP server exposes the store to an agent through a reader that cannot write.

The seal detects changes after the fact. It does not stop someone who can write the store before a row is published, so keep the store in another OS user or container. See [docs/ledger.md](../ledger.md) and [docs/audit-trail-dev/](../audit-trail-dev/).

## New: optional connectors for `import-logs`

`import-logs` can hand events to a connector you name explicitly with `--connector`, `--connector-option` or `--connector-config`. Nothing is discovered, imported or sent unless you name it. Secrets are written as `env:VAR`, and option values never appear in output. A configuration error exits `2` before any file is opened. With `--once`, events that were not delivered, were rejected or were dropped also exit `2`. `agent-latch-runtime connectors` lists what is installed. `--database` does not go through connectors. See [docs/connectors.md](../connectors.md).

## Upgrading

- There are no new static findings and no change to scan report formats, exit codes or `--fail-on` behavior.
- Check the runtime proxy change above if you run `agent-latch-runtime proxy` without flags.
- GitHub Action: `uses: AgentLatch/agent-latch@v0.6.0`
- pre-commit: `rev: v0.6.0`, or run `pre-commit autoupdate`
- pip: `pip install --upgrade agentlatch-security`
- Containers: `ghcr.io/agentlatch/agent-latch:0.6.0` and `ghcr.io/agentlatch/agent-latch-runtime:0.6.0`
