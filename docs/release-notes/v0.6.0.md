AgentLatch v0.6.0 adds optional connectors to the runtime importer, so stores, exporters and archives can be installed as separate packages, and seals the runtime event store so a changed store is detected. It also adds four runtime gates and improves a fifth.

> **Early proof of concept.** The scanner uses static heuristics, and the runtime side records traffic and reports findings only. Neither is a security guarantee. A clean scan does not mean an agent is safe.

## New: optional connectors for `import-logs`

`agent-latch-runtime import-logs` can now hand each batch of events to an installed connector: a package that stores them, exports them, or archives them somewhere else. The core defines the contract and runs the connectors. It ships none, depends on none, and sends nothing anywhere unless you name a connector.

```sh
agent-latch-runtime connectors            # list installed connector types (imports none of them)
agent-latch-runtime import-logs --connector wh=webhook --connector-option wh.url=env:AGENT_WEBHOOK_URL ...
```

- New options: `--connector`, `--connector-option` and `--connector-config`. Secrets are passed as `env:VAR` references, never on the command line.
- The runner batches events, retries a failed batch unchanged with a 1 to 60 s backoff, keeps a bounded queue, and writes batches a connector refuses to `<name>.rejected.jsonl`. One failing connector does not stop the others or the importer.
- Payloads stay off unless you turn them on with the `payloads` option, and a connector receives them only when you opt in.
- `--database` and every existing command line behave as before.

The contract is in [docs/connectors.md](../connectors.md). Licensing for separately distributed packages is in [docs/connector-licensing.md](../connector-licensing.md). The contract module, `agent_latch.runtime.connectors`, is public and MIT-licensed, so third-party and commercial connectors can build on it. **This is the first release that contains it**, so a connector package must require `agentlatch-security>=0.6.0`.

## New: a sealed event store

Every row written by `import-logs --database` now carries a seal: a SHA-256 over the event and its import time, chained to the row before it. A store whose rows were edited, removed or reordered, or whose layout was changed, is refused. The newest seal can be published to an anchor outside the agent's reach, so a store rebuilt from scratch is caught too. `agent-latch scan --runtime-result --database FILE` reports the verdict. See [docs/ledger.md](../ledger.md).

## New: store packages for the sealed events (`--store`)

The sealed events can now be kept by an installed store package instead of a SQLite file. `--store TYPE` (with `--store-option KEY=VALUE`, secrets as `env:VAR`) works wherever `--database FILE` does: `import-logs`, `verify`, `anchor`, `audit-tool` and `agent-latch --runtime-result`. The seals, the refusals, the anchors and the exit codes are the same code. `agent-latch-runtime stores` lists what is installed. The core ships no store package and depends on none. A connector can also ask for each event's seal (`wants_seals = True`), and then receives it once the store has saved the event. See [docs/stores.md](../stores.md).

## Runtime gates

- **ALR03**, tool and agent endpoint trust: records the MCP handshake and reports a server that did not name itself, or whose name or version changed during a run.
- **ALR04**, tool schema injection: rebuilt as deterministic, clause-level checks with the outcomes FAIL, INCONCLUSIVE and PASS, plus SARIF export.
- **ALR05**, instruction-like content in tool results: three detectors (`R01` instruction-like text, `R02` hidden or encoded instructions, `R03` steering toward another tool, destination or URL).
- **ALR10**, secrets crossing the tool boundary: `R01` a secret-like value sent to a tool, `R02` one returned from a tool. It works on masked payloads and never stores a value.
- **ALR16**, package installs: detects more fetch-and-run, direct-URL and registry-bypass patterns, and inspects nested base64 and hex commands.

These gates report findings. They do not block anything.

## Upgrading

No existing command line, report format, exit code or `--fail-on` behavior changed. `audit-tool` now takes `--database` or `--store`, so running it with neither names both in the error. The new gates add records to runtime reports, so a runtime report can now contain findings it did not before.
