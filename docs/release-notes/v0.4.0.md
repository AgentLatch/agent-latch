AgentLatch v0.4.0 is the first release on PyPI, as [`agentlatch-security`](https://pypi.org/project/agentlatch-security/). It also turns the runtime proxy's logs into reviewable events and adds the first runtime check, ALR04. The scanner, its rules and the GitHub Action are unchanged.

> **Early proof of concept.** The scanner uses static heuristics, and the runtime side records traffic and reports findings only. Neither is a security guarantee.

## New: install from PyPI

```sh
pipx install agentlatch-security
# or, in a virtual environment:
python -m pip install agentlatch-security
python -m pip install "agentlatch-security[runtime]"   # adds the MCP runtime proxy
```

The package is named `agentlatch-security` because PyPI rejects `agent-latch` as too similar to an existing, unrelated project called `agentlatch`. Only the package name differs: the commands are still `agent-latch` and `agent-latch-runtime`, the import is still `agent_latch`, and the Action is still `AgentLatch/agent-latch`. The PyPI package `agentlatch` is not AgentLatch.

Releases are published from GitHub Actions with PyPI Trusted Publishing, so no upload token exists.

## New: runtime events and findings (preview)

- **Full payloads, opt-in.** `agent-latch-runtime proxy --payloads FILE` also records full argument values and tool output, secret-masked and cut to `--payload-max-chars`. The default trace still holds only names, sizes, hashes and short masked excerpts.
- **`agent-latch-runtime import-logs`** runs next to the proxy, reads its log files, and joins each request, payload and response into one event. It prints one line per event and writes `events.csv` and `normalized.jsonl` under `runtime-logs/`. It never changes or blocks traffic.
- **ALR04 gate.** The importer runs ALR04, which reports a finding when an MCP tool definition (name, description or schema) contains instruction-like content, mapped to ASI01, ASI02 and ASI04. Results go to `gate-results.csv`. ALR04 reports findings only; it does not clear a tool or block a call.
- **`agent-latch --runtime-result`** prints the runtime findings in the same table as a scan, with a local tool's file and line when the project defines that function.
- **`--database FILE`** keeps each event in a local SQLite file as well. It is off unless set, uses only the standard library, and creates the file with mode `0600` where supported. Nothing is uploaded.
- **`agent-latch-runtime demo`** runs the whole flow against a bundled synthetic MCP server, so you can see the output with one command.

Read [docs/runtime.md](../runtime.md) for setup, what is recorded, and limits.

## Upgrading

The scanner and Action behave as in v0.3.0. Pin the new tag:

```yaml
- uses: AgentLatch/agent-latch@v0.4.0
  with:
    fail-on: high
```

If you installed from GitHub with `pip install "agent-latch @ git+https://..."`, switch to `pip install agentlatch-security`. Uninstall the old one first (`pip uninstall agent-latch`), because the two distributions install the same commands.
