AgentLatch v0.3.0 adds a first preview of runtime checks: a proxy that sits between an AI app and an MCP server and records the tool traffic. The scanner, its rules and the GitHub Action are unchanged.

> **Early proof of concept.** The scanner uses static heuristics, and the runtime proxy only records traffic. Neither is a security guarantee.

## New: runtime proxy for MCP (preview)

`agent-latch-runtime proxy` puts AgentLatch in front of one MCP server. You change one entry in your app's MCP config (Claude Desktop, Claude Code, Cursor and other MCP clients); the agent and the server stay as they are.

```json
"github": {
  "command": "agent-latch-runtime",
  "args": ["proxy", "--trace", "trace.jsonl", "--", "npx", "-y", "@modelcontextprotocol/server-github@<version>"]
}
```

- **Records** tool lists, tool calls and results, errors, and prompt templates (`prompts/list`, `prompts/get`), one JSON line per message (`agentlatch.runtime.trace/1`), plus a one-line summary on stderr.
- **Monitor only.** Every message passes through unchanged. Nothing is detected or blocked yet; detectors and opt-in blocking are planned.
- **Keeps values out of the log.** Records hold argument names, sizes and SHA-256 hashes, never argument values or full outputs. Output excerpts are short, with secret-like values (API keys, tokens, private keys) replaced by `[REDACTED]`; `--excerpt-chars 0` turns them off. The trace file is created with mode `0600`.
- **Two ways to run:** over stdio (the app starts the proxy, which starts the server after `--`), or as a loopback-only HTTP service in front of a remote server (`--http 127.0.0.1:8770 --upstream-url URL`).
- The child server receives the proxy's environment, so tokens set in the app's config still reach it.

Install the `runtime` extra pinned to this release; AgentLatch is not published on PyPI:

```sh
python -m pip install "agent-latch[runtime] @ git+https://github.com/AgentLatch/agent-latch.git@v0.3.0"
```

Read [docs/runtime.md](../runtime.md) for setup, what is recorded, and limits.

**Limits.** The proxy sees only servers whose config entry goes through it. The app's built-in tools and the user's prompts to the model don't pass through it. Known issues: over HTTP one tool call can also record an extra `tools/list` entry, and `session_id` can change between requests on the same connection. Tested on Linux, on WSL with Claude Desktop, and natively on Windows 11 (Python 3.13, installed from GitHub, stdio and HTTP, a real MCP server); macOS has not been tested yet. On Windows, keep the virtual environment path short (see the docs).

## Also new

- **Local MCP gateway** in [`mcp-server/`](../../mcp-server/README.md): one MCP server that gives an agent your local Python tools plus the MCP servers listed in `servers.json`, with tokens kept in a git-ignored `.env`. A developer tool for running agents against real tools; see [SETUP.md](../../mcp-server/SETUP.md).

## Upgrading

The scanner and Action behave as in v0.2.1. Pin the new tag:

```yaml
- uses: AgentLatch/agent-latch@v0.3.0
  with:
    fail-on: high
```
