AgentLatch v0.2.0 scans agent projects without needing a manifest and treats the scanned project as untrusted, so a project cannot hide its own findings. It adds the first checks for OWASP ASI08 Cascading Failures and ASI09 Human-Agent Trust Exploitation.

> **Early proof of concept.** Checks are static heuristics. A clean scan means only that the enabled checks found nothing, not that an agent is secure.

## ⚠️ Upgrading from v0.1.0

**Suppressions inside the scanned project are no longer applied by default.** That covers `.agent-latch-ignore`, `[tool.agent-latch] exclude` in `pyproject.toml`, and inline `# agent-latch: ignore` comments. Whoever controls a project controls these files, so applying them automatically let a third-party agent hide findings.

If your own repository relies on them, opt in:

| Where | Change |
|---|---|
| Command line | add `--project-ignores` |
| GitHub Action | add `project-ignores: "true"` under `with:` |
| pre-commit hook | nothing to do; the hook passes `--project-ignores` |
| Interactive mode | answer **yes** when asked whether to apply the project's own ignore file |

`--exclude` and an explicit `--ignore-file` always apply. On pull requests from people you don't fully trust, keep `project-ignores` off, or protect `.agent-latch-ignore` with CODEOWNERS.

Other changes you may notice:

- **More files are scanned.** Every folder and text file is checked. Folders named `venv` or `node_modules` are skipped only when they really are installed environments.
- **Secret findings in test files are now `low` severity** and no longer fail `--fail-on high`.
- **ASI09 was added to the mapping** of `AG004` and `MAN001` (missing confirmation for sensitive actions).

## Highlights

- **No manifest needed.** Agent checks run on source and prompt files directly. A manifest adds `MAN*` checks; it can add findings but never hides them.
- **Project suppressions are opt-in** with `--project-ignores` (see above).
- **Whole-project scanning.** Prompts in Python code, prompt-like keys in any YAML file (for example CrewAI `config/agents.yaml`), prompt template files (`.prompt`, `.j2`, `.jinja`, `prompts/*.md`), and secrets in every text file, including JSON and JavaScript.
- **Less noise.** `SEC001` skips obvious placeholders (`your-…`, `test-…`, `${VAR}`, `<value>`, translation labels), and `PRM002` ignores numeric placeholders such as `{message_count}`. On one large open-source agent framework, high-severity findings dropped from 357 to 42 with no real findings lost.
- **OWASP ASI01–ASI10 summary** in every report format (terminal, text, JSON `owasp_agentic`, SARIF `owaspAgenticCoverage`). Categories without rules are shown as `no checks yet`.

## New rules

| Rule | Detects | OWASP Agentic mapping |
|---|---|---|
| `AG004` | A function exposed to the model as a tool that runs commands, writes files or databases, sends email, or sends HTTP writes, with no approval gate in the file | ASI02; ASI05 or ASI03; ASI09 |
| `AG005` | Unrestricted built-in tools: `ShellTool`, `PythonREPLTool`, `load_tools(["terminal"])`, `CodeInterpreterTool(unsafe_mode=True)`, unscoped `FileManagementToolkit`, `allow_dangerous_requests=True` | ASI02; ASI05 or ASI03 |
| `AG006` | Human approval turned off: AutoGen `human_input_mode="NEVER"` with code execution, `auto_approve=True`, `permission_mode="bypassPermissions"`, `require_approval="never"`, and similar | ASI09; ASI05 or ASI02 |
| `AG007` | Agent loop without an effective limit: `max_iterations=None`, limits over 100, `recursion_limit` set very high, or `while True:` around an agent call with no exit | ASI08 |

`PRM001` and `PRM002` now also run on prompts in code, YAML, and prompt template files, not only in manifests.

ASI08 and ASI09 coverage is partial: these rules find missing safeguards in code, not runtime behavior. ASI06, ASI07, and ASI10 still have no checks.

## Other changes

- New CLI flag `--project-ignores`, a new GitHub Action input `project-ignores` (default `"false"`), and a new interactive-mode question (default **No**).
- When a scanned project's `.agent-latch-ignore` is not applied, the CLI says so on stderr.
- `SEC001` now matches JSON- and JavaScript-style keys such as `"api_key": "..."`.
- Faster AST traversal: scans are no slower than v0.1.0 despite the additional checks.

## Quick start

```sh
pip install "git+https://github.com/AgentLatch/agent-latch.git@v0.2.0"
agent-latch scan /path/to/my-agent
```

GitHub Actions:

```yaml
- uses: AgentLatch/agent-latch@v0.2.0
  with:
    fail-on: high
```

Full rule behavior and blind spots: [docs/RULES.md](../RULES.md). OWASP mappings are informational, not an OWASP endorsement or certification.
