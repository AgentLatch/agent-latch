AgentLatch v0.5.1 publishes the scanner and the runtime proxy as container images on the GitHub Container Registry. The scanner itself is unchanged from v0.5.0.

> **Early proof of concept.** The scanner uses static heuristics, and the runtime side records traffic and reports findings only. Neither is a security guarantee. A clean scan does not mean an agent is safe.

## New: container images on GHCR

Two images, published from this release onward with the tags `0.5.1`, `0.5` and `latest`:

| Image | Command | Use it to |
|---|---|---|
| `ghcr.io/agentlatch/agent-latch` | `agent-latch` | Scan a project, locally or in any CI system, without installing Python |
| `ghcr.io/agentlatch/agent-latch-runtime` | `agent-latch-runtime` | Run the MCP runtime proxy (preview), `import-logs`, `verify`, `anchor` and `demo` |

```sh
docker run --rm -v "$PWD:/src:ro" ghcr.io/agentlatch/agent-latch:0.5.1 scan . --fail-on high
```

Mount the project read-only (`:ro`). The scanner never writes to it.

- Both images support `linux/amd64` and `linux/arm64`.
- They run as a non-root user and hold no Node.js, no compiler and no source tree.
- The base image is pinned by digest, and dependencies are installed from hash-pinned locks as prebuilt wheels only, so no package's setup code runs when an image is built.
- Each published image carries signed build provenance and an SBOM. Verify one with `gh attestation verify oci://ghcr.io/agentlatch/agent-latch:0.5.1 --owner AgentLatch`.
- The runtime image proxies a remote server (`--upstream-url`) or a server command that exists inside the image. It contains no Node.js, so `npx` servers need their own container or a derived image. The proxy's HTTP mode stays loopback-only and cannot be reached from outside a container; use stdio (`docker run -i`).

Setup, connecting an app and the limits are in [docs/docker.md](../docker.md) and [docs/docker-setup.md](../docker-setup.md). The runtime proxy is still a preview: it records and reports, and never blocks.

## Upgrading

No scanner or runtime code changed, so there are no new findings, and no change to report formats, exit codes or `--fail-on` behavior. Moving from `v0.5.0` to `v0.5.1` changes only the version number, plus the container images and docs.

- GitHub Action: `uses: AgentLatch/agent-latch@v0.5.1`
- pre-commit: `rev: v0.5.1`, or run `pre-commit autoupdate`
- pip: `pip install --upgrade agentlatch-security`

## Behind the scenes

- The release workflow for the images is separate from the PyPI workflow. Both start when a GitHub release is published, and each can be re-run on its own.
- Workflow actions are pinned to commit SHAs, and Dependabot proposes weekly updates for the base image, the actions and the image dependency locks.
- Pull requests that change the PyPI publish workflow now run a dry run that builds and checks the distributions without publishing.
