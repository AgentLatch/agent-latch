AgentLatch v0.5.0 groups every check under a gate (a security outcome), adds 13 static detectors, including the first checks for OWASP Agentic ASI06, ASI07 and ASI10, and adds a tamper-evident audit ledger for runtime traces (ALR15).

> **Early proof of concept.** The scanner uses static heuristics, and the runtime side records traffic and reports findings only. Neither is a security guarantee. A clean scan does not mean an agent is safe.

## New: gates

Each detector, static or runtime, now belongs to exactly one gate, for example `ALR06` (no unsandboxed code execution) or `ALR09` (human approval for sensitive actions). [docs/GATES.md](../GATES.md) lists every gate, its detectors, and the OWASP Agentic and EU AI Act references for each. These references are informational only and are not a compliance claim.

- The terminal, text report, `--fail-on` summary and Action job summary show short IDs with their gate, for example `PY001 (ALR06)`.
- SARIF `ruleId` and JSON `rule_id` keep the full ID (`AGENTLATCH-PY001`), so existing code-scanning alert history carries over. JSON and SARIF also add `gate` and `short_id`.
- Ignore files accept the new detector IDs (`ALRnn-Snn` for static rules, `ALRnn-Rnn` for runtime checks).

## New: 13 static detectors

| ID | Gate | OWASP | Severity | Detects |
|---|---|---|---|---|
| `ALR01-S01` | `ALR01` | ASI01 | medium | Invisible, bidi or zero-width characters in a prompt |
| `ALR03-S01` | `ALR03` | ASI03, ASI07 | medium | Agent or MCP server bound to every interface (`0.0.0.0`) |
| `ALR06-S01` | `ALR06` | ASI05 | high or medium | Unsafe deserialization (`pickle`, `yaml.load`, `torch.load`, dangerous loader options) |
| `ALR06-S02` | `ALR06` | ASI02, ASI05 | high or medium | Model-written code run without a sandbox |
| `ALR08-S01` | `ALR08` | ASI08 | medium | Outbound HTTP call without a timeout |
| `ALR08-S02` | `ALR08` | ASI08 | medium | Retry without a limit |
| `ALR11-S01` | `ALR11` | ASI04 | high | `trust_remote_code=True` on a model or dataset loader |
| `ALR12-S01` | `ALR12` | ASI02, ASI07 | medium | Plaintext `http://` or `ws://` endpoint |
| `ALR13-S01` | `ALR13` | ASI06 | medium | Web or tool output written to memory without validation |
| `ALR13-S02` | `ALR13` | ASI06 | low | Memory shared across sessions (module-level store) |
| `ALR14-S01` | `ALR14` | ASI10 | medium | Agent writes to its own prompts or settings |
| `ALR14-S02` | `ALR14` | ASI10 | high | Agent installs persistence on the host |
| `ALR14-S03` | `ALR14` | ASI10 | medium | Agent installs packages at runtime |

ASI06, ASI07 and ASI10 now report `partial` instead of `no checks yet`, and ASI08 gains two checks beside `AG007`. Partial means a few patterns are checked, not that the category is covered. [docs/RULES.md](../RULES.md) lists what each rule finds and what it misses.

## New: tamper-evident audit ledger, ALR15 (preview)

A trace file is useful as evidence only if nobody can quietly rewrite it. `agent-latch-runtime proxy --trace FILE --ledger FILE` seals every trace record into a local hash chain. `agent-latch-runtime anchor` writes one short digest to a location you choose that the agent cannot write to.

```sh
agent-latch-runtime proxy --trace runtime-logs/trace.jsonl \
  --ledger runtime-logs/trace.ledger.jsonl -- <server command>
agent-latch-runtime anchor --ledger runtime-logs/trace.ledger.jsonl --to /mnt/audit/anchors.jsonl
agent-latch-runtime verify --ledger runtime-logs/trace.ledger.jsonl \
  --trace runtime-logs/trace.jsonl --anchor /mnt/audit/anchors.jsonl
```

- `verify` reports one of six verdicts: `intact`, `unanchored`, `tampered`, `deleted`, `rewritten` or `missing`. `verify FOLDER` checks every ledger in a folder (`--all` adds subfolders) and prints one row for each.
- `agent-latch --runtime-result --ledger FILE [--anchor PATH]` prints the verdict first, followed by a table with one row per record. `--ledger-rows N` limits the intact rows shown; problem records are always shown. `--format sarif` exports each problem as an `ALR15-R01` result.
- The ledger uses the standard library only and makes no network request. It never blocks a call: if an append fails, the proxy prints one warning and carries on.
- The ledger proves only that a log was not changed after it was recorded. It does not show that the recorded actions were safe, and without an anchor it cannot catch a full rewrite.

Start with [the audit ledger](../ledger.md), then [setup](../ledger-setup.md), [reference](../ledger-reference.md) and [operations](../ledger-operations.md).

## Fixes and smaller changes

- `--output` pointing to a path that cannot be written now prints a clear error and exits `2` instead of crashing.
- The README, CONTRIBUTING and the new-issue page link to GitHub Discussions for questions and rule ideas.
- CI runs ruff across the whole repo and `npm audit` for the web dashboard.

## Upgrading

```sh
pipx upgrade agentlatch-security
# or
python -m pip install -U "agentlatch-security==0.5.0"
```

```yaml
- uses: AgentLatch/agent-latch@v0.5.0
  with:
    fail-on: high
```

- **Expect new findings.** The 13 new detectors can report on code that passed before. With `fail-on: high`, these can newly fail a build: `ALR11-S01`, `ALR14-S02`, and the high-severity cases of `ALR06-S01` and `ALR06-S02`. Review them before you upgrade a required check, or start with `fail-on: none` until you have reviewed the new findings.
- **Report text changed.** Rule IDs in the terminal and text reports now include the gate (`PY001 (ALR06)`). If a script parses that text, read JSON or SARIF instead. Their full IDs did not change.
- **Exit codes** for scans are unchanged. One addition: `--runtime-result` with `--ledger` exits `1` when the trail fails verification, even with `--fail-on none`, and `2` when the ledger path is missing. Runs without `--ledger` behave as before.
