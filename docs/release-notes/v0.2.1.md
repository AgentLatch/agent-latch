AgentLatch v0.2.1 fixes a security issue in the GitHub Action, adds a summary overview to the job page, and lets you hide low-severity findings.

> **Early proof of concept.** Checks are static heuristics. A clean scan means only that the enabled checks found nothing, not that an agent is secure.

## 🔒 Security fix: GitHub Action

In v0.1.0 and v0.2.0, the Action ran Python inside the scanned repository's folder with `python -m venv`, `python -m pip`, and `python -`. Those forms put the current directory first on Python's import path. A scanned repository that contained a planted module, such as `json.py`, `venv/`, or `pip/`, could therefore run its own code inside the Action's steps.

Every Python call in the Action now uses isolated mode (`-I`), which ignores the current directory. The risk was highest in workflows that check out code from untrusted pull requests with elevated permissions (for example `pull_request_target`).

**Upgrade by pinning `AgentLatch/agent-latch@v0.2.1`.** No other workflow changes are needed.

## Highlights

- **Job summary overview.** The Action's summary page now opens with a pass/fail headline and finding counts by severity, by rule, and by OWASP ASI01–ASI10 category. It then lists the findings that fail the job, with all other findings collapsed. Text from the scanned project, such as file names and evidence, is escaped so it cannot inject links or HTML into the page.
- **Shorter step log.** The summary step prints a two-line total instead of every finding. The scan step still lists the findings that fail the job.
- **`--min-severity`** (Action input `min-severity`): report only findings at or above a severity, for example `--min-severity medium`. Hidden findings are counted in every report, and unknown-severity findings are always shown. It cannot be set above `--fail-on`, so it never hides a finding that would fail the scan.
- **Fewer test-file alerts.** `eval`/`exec` (`PY001`) and risky tools without approval (`AG004`) in test files are now reported at **low** severity, like `SEC001`, `AG006`, and `AG007`. On one large open-source agent framework, findings at `--fail-on high` dropped from 42 to 31.

## Report format additions

- JSON: `min_severity` and `hidden_below_min_severity`.
- SARIF `runs[0].properties`: `suppressedCount`, `minSeverity`, and `hiddenBelowMinSeverityCount`.

## Upgrading

```yaml
- uses: AgentLatch/agent-latch@v0.2.1
  with:
    fail-on: high
    # min-severity: medium   # optional
```

If you are upgrading from v0.1.0, read the [v0.2.0 notes](v0.2.0.md) first: suppressions inside the scanned project now need `project-ignores: "true"`.
