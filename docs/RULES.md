# Detection rules and OWASP mapping notes

AgentLatch v0.2.0 contains a few deterministic source-pattern and agent-manifest checks. Every rule except `MAN*` works from source alone; a manifest adds checks but is never required, and it can only add findings, never hide them. A hit means “review this code,” not “this code is exploitable.” A clean result means only that these patterns were not found in the scanned files.

Each rule belongs to one gate, the security outcome it provides evidence for. [GATES.md](GATES.md) lists the gates. Rules are written short here (`PY001`). Reports show them with their gate (`PY001 (ALR06)`), SARIF and JSON keep the full ID (`AGENTLATCH-PY001`), and suppressions accept either form.

| Rule | Gate | Detection | OWASP Agentic Top 10 mapping | Limitations |
|---|---|---|---|---|
| PY001 | `ALR06` | Python direct calls to `eval()` or `exec()` | ASI05 Unexpected Code Execution (RCE); ASI02 Tool Misuse and Exploitation | Does not establish whether the argument is attacker-controlled; misses indirect invocation and aliases. In test files, findings are low severity. |
| PY002 | `ALR06` | `subprocess.*(..., shell=True)` | ASI05 Unexpected Code Execution (RCE); ASI02 Tool Misuse and Exploitation | Does not prove command injection; misses wrappers and aliases. |
| PY003 | `ALR12` | A call with literal `verify=False` | ASI02 Tool Misuse and Exploitation | Heuristic; does not resolve the called library or runtime context. |
| AG001 | `ALR07` | `Agent(..., allow_delegation=True)` | ASI02 Tool Misuse and Exploitation; ASI03 Identity and Privilege Abuse | CrewAI-specific review hint, not automatically a vulnerability. |
| SEC001 | `ALR10` | Credential-like assignment (`api_key`, `secret`, `password`, `access_token`, `auth_token`) to a quoted literal of 8+ characters, in any text file, including JSON and JavaScript object keys | ASI03 Identity and Privilege Abuse; ASI04 Agentic Supply Chain Vulnerabilities | Heuristic; may miss encoded or dynamic secrets. Skips obvious placeholders: values starting with `your`, `test`, `fake`, `dummy`, `mock`, `example`, `my-`, or `not-`; `${VAR}`, `{{ var }}`, `<value>`, and `$VAR` references; values that repeat the key's name (`"password": "Password"`); JSON-escaped text; and letter-only values in translation folders (`translations/`, `locales/`, `i18n/`). In test files (`tests/`, `test_*.py`, `*_test.*`, `*.test.*`, `*.spec.*`, `conftest.py`), findings are **low** severity and low confidence instead of high. Values are redacted. |
| AG002 | `ALR06` | LangChain `create_pandas_dataframe_agent(...)` factory call | ASI05 Unexpected Code Execution (RCE); ASI02 Tool Misuse and Exploitation | Flags the capability for review even when guarded by a runtime flag; it does not prove that the dangerous option is enabled in every execution. |
| AG003 | `ALR05` | Output of a known web-search tool, web loader, or HTTP client (`requests`, `httpx`, `urlopen`) reaching `HumanMessage`/`SystemMessage`/`ChatMessage` content or a `{"role": ..., "content": ...}` message, traced through assignments, loops, returns, call arguments, and LangGraph-style state keys | ASI01 Agent Goal Hijack | Single-file, name-based tracking: misses aliases, attributes, cross-module flow, and unlisted tools; may over-report when the same key name is reused. Content fenced in tag-like delimiters (`<page>...</page>`) or labelled untrusted is treated as mitigated. Low confidence. |
| AG004 | `ALR09` | A function exposed to the model as a tool (`@tool`, `@function_tool`, `@kernel_function`, a `BaseTool` subclass, `Tool(func=...)`/`StructuredTool.from_function`, or a function listed in `tools=[...]`) that runs shell commands or code, writes or deletes files, sends email, writes to a database, or sends HTTP write requests, directly or through one same-file helper, with no approval gate in the file (`interrupt()`, `interrupt_before`, `HumanApprovalCallbackHandler`, `HumanInTheLoopMiddleware`, `needs_approval=True`, or an `approve`/`confirm` call) | ASI02 Tool Misuse and Exploitation; ASI05 Unexpected Code Execution (RCE) for code execution, otherwise ASI03 Identity and Privilege Abuse; ASI09 Human-Agent Trust Exploitation (missing confirmation for sensitive actions) | Works without a manifest. Single-file, name-based: misses tools registered in another module and approval enforced elsewhere (for example in the host app); any approval marker anywhere in the file suppresses every tool in it. In test files, findings are low severity. |
| AG005 | `ALR07` | An agent given an unrestricted built-in tool: `ShellTool`, `PythonREPLTool`, `load_tools([...])` with `terminal`/`shell`/`python_repl`, `CodeInterpreterTool(unsafe_mode=True)`, `FileManagementToolkit` without `root_dir` or `selected_tools`, or `allow_dangerous_requests=True` | ASI02 Tool Misuse and Exploitation; ASI05 Unexpected Code Execution (RCE) or ASI03 Identity and Privilege Abuse | Works without a manifest. Matches class and function names only; a sandbox configured outside the call is not seen. |
| AG006 | `ALR09` | Human approval turned off: AutoGen `human_input_mode="NEVER"` while code execution is on; `auto_approve`, `auto_approve_tools`, `auto_confirm`, `skip_approval`, `skip_confirmation`, `bypass_approval`, `dangerously_skip_permissions`, or `yolo` set to `True`; `approval_mode`, `approval_policy`, `permission_mode`, or `require_approval` set to `never`, `none`, `auto`, `always_approve`, `bypassPermissions`, `full-auto`, or `yolo` | ASI09 Human-Agent Trust Exploitation; ASI05 Unexpected Code Execution (RCE) for AutoGen code execution, otherwise ASI02 Tool Misuse and Exploitation | Literal keyword values only; settings loaded from config files or environment variables are missed. In test files, findings are low severity. |
| AG007 | `ALR08` | Agent loop without an effective limit: `max_iterations`, `max_iter`, `max_turns`, `max_round(s)`, `max_steps`, or `recursion_limit` set to `None`, `math.inf`, `sys.maxsize`, or more than 100 (as a keyword or a config-dict key); or `while True:` around an agent call (`invoke`, `kickoff`, `initiate_chat`, `Runner.run_sync`, or `run`/`chat`/`stream` on an agent-, crew-, or graph-like object) with no `break`, `return`, `raise`, or `sys.exit` | ASI08 Cascading Failures | A partial ASI08 check: it finds missing circuit breakers, not cascades. Limits set elsewhere and loops that exit through exceptions raised in called functions are not seen. In test files, findings are low severity. |
| DEP001 | `ALR11` | A known vulnerability advisory for a requirement | ASI04 Agentic Supply Chain Vulnerabilities | Requires `--dependencies`; only scans `requirements*.txt`; advisory coverage depends on the configured vulnerability service and package/version data. `pip-audit` does not provide normalized severity here, so severity is reported as `unknown`. Duplicate package/version/advisory records are collapsed. |
| MAN001 | `ALR09` | Manifest tool with a high-risk capability (shell, code execution, filesystem/database write, payments, email send, admin) and no `requires_approval`, `human_in_the_loop`, or `require_confirmation` | ASI02 Tool Misuse and Exploitation; ASI05 Unexpected Code Execution (RCE) for code execution, otherwise ASI03 Identity and Privilege Abuse; ASI09 Human-Agent Trust Exploitation | Only sees what the manifest declares; capability names are matched against a fixed list. |
| MAN002 | `ALR07` | Manifest tool with wildcard permissions (`*`, `all`, `any`, or `scope:*`) | ASI02 Tool Misuse and Exploitation; ASI03 Identity and Privilege Abuse | Declared scope only; does not check what credentials the tool actually holds. |
| MAN003 | `ALR03` | Manifest tool with an `endpoint`/`url`/`base_url`/`server` and `auth` missing or set to `none` | ASI03 Identity and Privilege Abuse; ASI02 Tool Misuse and Exploitation | Missing `auth` is reported with low confidence; auth may be handled elsewhere. |
| PRM001 | `ALR01` | Instruction-override phrases (for example “ignore all previous instructions”) in prompts found in Python code (`SystemMessage`, `("system", ...)` tuples, `{"role": ...}` dicts, CrewAI `goal`/`backstory`, `instructions=`, `*_PROMPT` variables), prompt-like keys in any YAML file (for example CrewAI `config/agents.yaml`), prompt template files (`.prompt`, `.prompty`, `.j2`, `.jinja`, `.jinja2`, and `.md`/`.txt` under a `prompts/` folder), manifest prompts, and prompt files a manifest references | ASI01 Agent Goal Hijack | Fixed English signatures; paraphrased, encoded, or non-English injections are missed. Security-training text can match. |
| PRM002 | `ALR01` | A user-input-like placeholder (`{user_input}`, `{{ query }}`, `${message}`) inside a system prompt: a system-role message or keyword in code or YAML, a manifest `system_prompt`, or a prompt file whose name contains `system` | ASI01 Agent Goal Hijack | Name-based heuristic; reports low confidence. Names ending in `_count`, `_id`, `_len`, `_total`, `_index`, `_type`, `_size`, or `_time` are skipped because they hold numbers or identifiers, not user text. |
| ALR01-S01 | `ALR01` | Zero-width, bidi-control, soft-hyphen, or Unicode tag characters in a prompt found in code, YAML, a prompt template file, or a manifest | ASI01 Agent Goal Hijack | One finding per line, for the first such character. Zero-width joiners inside an emoji or a non-Latin word are skipped. It cannot tell who added the character; a copy-paste from a document also triggers it. |
| ALR03-S01 | `ALR03` | A call with a literal `host=`/`bind=` of `0.0.0.0`, `::`, or `[::]` (for example `uvicorn.run(app, host="0.0.0.0")`) | ASI03 Identity and Privilege Abuse; ASI07 Insecure Inter-Agent Communication | Flags the bind address, not the presence of authentication: a public bind can be intentional in a container. Low confidence. |
| ALR06-S01 | `ALR06` | `yaml.load`/`load_all` without a safe `Loader`, `pickle`/`dill`/`cPickle` `load`/`loads`, `torch.load` without `weights_only=True`, or `allow_dangerous_deserialization=True` | ASI05 Unexpected Code Execution (RCE) | Loader names are matched against a short unsafe list (`yaml.Loader`, `yaml.CLoader`, `yaml.UnsafeLoader`, `yaml.CUnsafeLoader`), so a custom loader is assumed safe; a variable named `loader` passed as `Loader=` also matches. `yaml.FullLoader`/`yaml.CFullLoader` are reported at medium severity: they avoid arbitrary object construction but are still not safe for untrusted input. Does not prove the data comes from an untrusted source. `torch.load` is medium severity because it is often used on local artifacts. |
| ALR06-S02 | `ALR06` | `use_docker=False`, `code_execution_mode="unsafe"`, `executor_type="local"`, or `allow_dangerous_code=True`, as a keyword or a config-dict key | ASI05 Unexpected Code Execution (RCE); ASI02 Tool Misuse and Exploitation | Only literal options are seen; a sandbox chosen in a config file or at runtime is missed. A framework default that is already unsandboxed is not reported. |
| ALR08-S01 | `ALR08` | `requests`, `httpx`, `urllib3`, or `urllib.request` call without a `timeout`/`timeout_ms` keyword, or an `aiohttp.ClientSession(...)` without `timeout=` | ASI08 Cascading Failures | Keyword only, and a literal `timeout=None` counts as no timeout: a timeout applied on a shared session or wrapper is missed. `aiohttp` is checked on the session, because its request methods take no `timeout=` argument. Does not measure how long a call actually blocks. |
| ALR08-S02 | `ALR08` | tenacity `@retry` without `stop=`/`stop_after_delay=`, `backoff.on_exception` without `max_tries=`/`max_time=`, `Retry(total=None)`, or `max_retries` set to `None` or more than 100 | ASI08 Cascading Failures | Name-based and import-blind: any decorator named `retry` or `on_exception` is treated as tenacity or backoff, so a project-local decorator with that name is reported too, and a retry configured on a shared client is missed. A bounded retry that is still too eager is not reported. |
| ALR11-S01 | `ALR11` | `trust_remote_code=True` passed to a model or dataset loader | ASI04 Agentic Supply Chain Vulnerabilities | Flags the option, not the repository: pinning a revision does not remove the risk. Remote code loaded by other mechanisms, such as a custom `auto_map`, is missed. |
| ALR12-S01 | `ALR12` | A literal `http://` or `ws://` value passed as `url`, `base_url`, `endpoint`, `server_url`, `mcp_url`, or a similar endpoint keyword, to a host other than `localhost`, `127.0.0.1`, or `::1` | ASI02 Tool Misuse and Exploitation; ASI07 Insecure Inter-Agent Communication | Endpoints built at runtime, read from configuration, or configured in MCP JSON files are missed. Plain HTTP between containers on a trusted network is still reported. Only the scheme and host are quoted in the report, never the full URL, so credentials in userinfo or a query string stay out of it. |
| ALR13-S01 | `ALR13` | Output of a known web-search tool, web loader, or HTTP client reaching `memory.*`, a `*store*`/`*collection*`/`*vector*` receiver's `add`/`save`/`upsert`/`put`/`insert`/`save_context`, or `add_memory`/`save_memory` | ASI06 Memory & Context Poisoning | Uses the same single-file taint analysis as `AG003`, with the same blind spots. A value passed through a helper named like `validate`/`sanitize`/`filter`/`clean` is treated as validated, which only reflects the name. Low confidence. |
| ALR13-S02 | `ALR13` | A module-level assignment from a call to a class whose name ends in `Memory` (`ConversationBufferMemory`, Mem0 `Memory`, ...) or a vector-store client (`Chroma`, `FAISS`, `Pinecone`, `QdrantClient`, ...) | ASI06 Memory & Context Poisoning | Module-level only; a memory built in a function and stored in a global is missed. Shared state can be deliberate in a single-user tool. Low severity, low confidence. |
| ALR14-S01 | `ALR14` | A write (`open(..., "w"/"a")`, `Path.write_text`/`write_bytes`, `os.replace`, `shutil.move`/`copy*`) whose destination is a `prompts/` or `instructions/` directory, a `.prompt`/`.prompty`/`.j2`/`.jinja`/`.jinja2` file, a `system_prompt*`/`system_message*`/`persona*`/`personality*` prompt file (a bare name, or a `.prompt`/`.prompty`/`.j2`/`.jinja`/`.jinja2` extension), `.env*`, `agent-manifest*`, `.mcp.json`, `settings.json`, or `.claude`/`.codex`/`.cursor` | ASI10 Rogue Agents | Matched by path segment, basename, or extension, so an output file that merely mentions `prompt` in its name (`prompt_results.json`, `system_prompt_audit.json`) is not reported, and a `system_prompt*`/`persona*` file with a data or document extension (`system_prompt.md`, `system_prompt.json`) is not treated as a prompt either. Only literal path text is inspected, so a path built from variables is missed. Writing anywhere else, including generated code, is not reported. In test files, findings are low severity. |
| ALR14-S02 | `ALR14` | A write to a cron, systemd, launchd, shell-profile, `authorized_keys`, or autostart path, or an executed command containing `crontab` (except `crontab -l`, which only lists entries), `systemctl enable`, `launchctl load`, `schtasks`, `nohup`, or `setsid` | ASI10 Rogue Agents | Matches the destination path or command text only, never the content being written. Installation or provisioning scripts in the same project also match. |
| ALR14-S03 | `ALR14` | An executed command (`os.system`, `os.popen`, `os.exec*`, `subprocess.*`, `pty.spawn`) containing a package install (`pip`, `uv pip`, `pipx`, `poetry`, `conda`, `npm`, `pnpm`, `yarn` ... `install`) | ASI10 Rogue Agents | Only the tool name is reported, never the full command line. Wrappers, shell scripts, and `pip` used through an API are missed. |
| MAN000 | — | A prompt file referenced by the manifest could not be read | — | Informational coverage note; does not affect `--fail-on`. |

## OWASP category list and coverage report

Category IDs and names are defined once in `src/agent_latch/owasp.py` (`ASI_CATEGORIES`), using the titles from the OWASP publication. A test checks that every rule maps only to those IDs.

Every report includes an ASI01–ASI10 summary: the text and terminal output show a table, JSON has an `owasp_agentic.categories` key, and SARIF has `runs[0].properties.owaspAgenticCoverage`. Each category is shown as one of:

- `N finding(s)`: enabled checks reported findings in this category.
- `no findings from enabled checks`: rules exist for this category but reported nothing. Some only run with a manifest or `--dependencies`, and none fully cover a category.
- `no checks yet`: AgentLatch has no rule for this category. No category is in this state today; the label stays so a newly listed OWASP category is never mistaken for a clean result.

OWASP category titles and mapping are informational references to the [OWASP Top 10 for Agentic Applications 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/). AgentLatch is independent and is not endorsed, approved, or certified by OWASP. Review the OWASP source for current definitions and version changes.
