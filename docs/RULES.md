# Detection rules and OWASP mapping notes

AgentLatch v0.2.0 contains a few deterministic source-pattern and agent-manifest checks. Every rule except `MAN*` works from source alone; a manifest adds checks but is never required, and it can only add findings, never hide them. A hit means “review this code,” not “this code is exploitable.” A clean result means only that these patterns were not found in the scanned files.

| Rule | Detection | OWASP Agentic Top 10 mapping | Limitations |
|---|---|---|---|
| AGENTLATCH-PY001 | Python direct calls to `eval()` or `exec()` | ASI05 Unexpected Code Execution (RCE); ASI02 Tool Misuse and Exploitation | Does not establish whether the argument is attacker-controlled; misses indirect invocation and aliases. |
| AGENTLATCH-PY002 | `subprocess.*(..., shell=True)` | ASI05 Unexpected Code Execution (RCE); ASI02 Tool Misuse and Exploitation | Does not prove command injection; misses wrappers and aliases. |
| AGENTLATCH-PY003 | A call with literal `verify=False` | ASI02 Tool Misuse and Exploitation | Heuristic; does not resolve the called library or runtime context. |
| AGENTLATCH-AG001 | `Agent(..., allow_delegation=True)` | ASI02 Tool Misuse and Exploitation; ASI03 Identity and Privilege Abuse | CrewAI-specific review hint, not automatically a vulnerability. |
| AGENTLATCH-SEC001 | Credential-like assignment (`api_key`, `secret`, `password`, `access_token`, `auth_token`) to a quoted literal of 8+ characters, in any text file, including JSON and JavaScript object keys | ASI03 Identity and Privilege Abuse; ASI04 Agentic Supply Chain Vulnerabilities | Heuristic; may miss encoded or dynamic secrets. Skips obvious placeholders: values starting with `your`, `test`, `fake`, `dummy`, `mock`, `example`, `my-`, or `not-`; `${VAR}`, `{{ var }}`, `<value>`, and `$VAR` references; values that repeat the key's name (`"password": "Password"`); JSON-escaped text; and letter-only values in translation folders (`translations/`, `locales/`, `i18n/`). In test files (`tests/`, `test_*.py`, `*_test.*`, `*.test.*`, `*.spec.*`, `conftest.py`), findings are **low** severity and low confidence instead of high. Values are redacted. |
| AGENTLATCH-AG002 | LangChain `create_pandas_dataframe_agent(...)` factory call | ASI05 Unexpected Code Execution (RCE); ASI02 Tool Misuse and Exploitation | Flags the capability for review even when guarded by a runtime flag; it does not prove that the dangerous option is enabled in every execution. |
| AGENTLATCH-AG003 | Output of a known web-search tool, web loader, or HTTP client (`requests`, `httpx`, `urlopen`) reaching `HumanMessage`/`SystemMessage`/`ChatMessage` content or a `{"role": ..., "content": ...}` message, traced through assignments, loops, returns, call arguments, and LangGraph-style state keys | ASI01 Agent Goal Hijack | Single-file, name-based tracking: misses aliases, attributes, cross-module flow, and unlisted tools; may over-report when the same key name is reused. Content fenced in tag-like delimiters (`<page>...</page>`) or labelled untrusted is treated as mitigated. Low confidence. |
| AGENTLATCH-AG004 | A function exposed to the model as a tool (`@tool`, `@function_tool`, `@kernel_function`, a `BaseTool` subclass, `Tool(func=...)`/`StructuredTool.from_function`, or a function listed in `tools=[...]`) that runs shell commands or code, writes or deletes files, sends email, writes to a database, or sends HTTP write requests, directly or through one same-file helper, with no approval gate in the file (`interrupt()`, `interrupt_before`, `HumanApprovalCallbackHandler`, `HumanInTheLoopMiddleware`, `needs_approval=True`, or an `approve`/`confirm` call) | ASI02 Tool Misuse and Exploitation; ASI05 Unexpected Code Execution (RCE) for code execution, otherwise ASI03 Identity and Privilege Abuse; ASI09 Human-Agent Trust Exploitation (missing confirmation for sensitive actions) | Works without a manifest. Single-file, name-based: misses tools registered in another module and approval enforced elsewhere (for example in the host app); any approval marker anywhere in the file suppresses every tool in it. |
| AGENTLATCH-AG005 | An agent given an unrestricted built-in tool: `ShellTool`, `PythonREPLTool`, `load_tools([...])` with `terminal`/`shell`/`python_repl`, `CodeInterpreterTool(unsafe_mode=True)`, `FileManagementToolkit` without `root_dir` or `selected_tools`, or `allow_dangerous_requests=True` | ASI02 Tool Misuse and Exploitation; ASI05 Unexpected Code Execution (RCE) or ASI03 Identity and Privilege Abuse | Works without a manifest. Matches class and function names only; a sandbox configured outside the call is not seen. |
| AGENTLATCH-AG006 | Human approval turned off: AutoGen `human_input_mode="NEVER"` while code execution is on; `auto_approve`, `auto_approve_tools`, `auto_confirm`, `skip_approval`, `skip_confirmation`, `bypass_approval`, `dangerously_skip_permissions`, or `yolo` set to `True`; `approval_mode`, `approval_policy`, `permission_mode`, or `require_approval` set to `never`, `none`, `auto`, `always_approve`, `bypassPermissions`, `full-auto`, or `yolo` | ASI09 Human-Agent Trust Exploitation; ASI05 Unexpected Code Execution (RCE) for AutoGen code execution, otherwise ASI02 Tool Misuse and Exploitation | Literal keyword values only; settings loaded from config files or environment variables are missed. In test files, findings are low severity. |
| AGENTLATCH-AG007 | Agent loop without an effective limit: `max_iterations`, `max_iter`, `max_turns`, `max_round(s)`, `max_steps`, or `recursion_limit` set to `None`, `math.inf`, `sys.maxsize`, or more than 100 (as a keyword or a config-dict key); or `while True:` around an agent call (`invoke`, `kickoff`, `initiate_chat`, `Runner.run_sync`, or `run`/`chat`/`stream` on an agent-, crew-, or graph-like object) with no `break`, `return`, `raise`, or `sys.exit` | ASI08 Cascading Failures | A partial ASI08 check: it finds missing circuit breakers, not cascades. Limits set elsewhere and loops that exit through exceptions raised in called functions are not seen. In test files, findings are low severity. |
| AGENTLATCH-DEP001 | A known vulnerability advisory for a requirement | ASI04 Agentic Supply Chain Vulnerabilities | Requires `--dependencies`; only scans `requirements*.txt`; advisory coverage depends on the configured vulnerability service and package/version data. `pip-audit` does not provide normalized severity here, so severity is reported as `unknown`. Duplicate package/version/advisory records are collapsed. |
| AGENTLATCH-MAN001 | Manifest tool with a high-risk capability (shell, code execution, filesystem/database write, payments, email send, admin) and no `requires_approval`, `human_in_the_loop`, or `require_confirmation` | ASI02 Tool Misuse and Exploitation; ASI05 Unexpected Code Execution (RCE) for code execution, otherwise ASI03 Identity and Privilege Abuse; ASI09 Human-Agent Trust Exploitation | Only sees what the manifest declares; capability names are matched against a fixed list. |
| AGENTLATCH-MAN002 | Manifest tool with wildcard permissions (`*`, `all`, `any`, or `scope:*`) | ASI02 Tool Misuse and Exploitation; ASI03 Identity and Privilege Abuse | Declared scope only; does not check what credentials the tool actually holds. |
| AGENTLATCH-MAN003 | Manifest tool with an `endpoint`/`url`/`base_url`/`server` and `auth` missing or set to `none` | ASI03 Identity and Privilege Abuse; ASI02 Tool Misuse and Exploitation | Missing `auth` is reported with low confidence; auth may be handled elsewhere. |
| AGENTLATCH-PRM001 | Instruction-override phrases (for example “ignore all previous instructions”) in prompts found in Python code (`SystemMessage`, `("system", ...)` tuples, `{"role": ...}` dicts, CrewAI `goal`/`backstory`, `instructions=`, `*_PROMPT` variables), prompt-like keys in any YAML file (for example CrewAI `config/agents.yaml`), prompt template files (`.prompt`, `.prompty`, `.j2`, `.jinja`, `.jinja2`, and `.md`/`.txt` under a `prompts/` folder), manifest prompts, and prompt files a manifest references | ASI01 Agent Goal Hijack | Fixed English signatures; paraphrased, encoded, or non-English injections are missed. Security-training text can match. |
| AGENTLATCH-PRM002 | A user-input-like placeholder (`{user_input}`, `{{ query }}`, `${message}`) inside a system prompt: a system-role message or keyword in code or YAML, a manifest `system_prompt`, or a prompt file whose name contains `system` | ASI01 Agent Goal Hijack | Name-based heuristic; reports low confidence. Names ending in `_count`, `_id`, `_len`, `_total`, `_index`, `_type`, `_size`, or `_time` are skipped because they hold numbers or identifiers, not user text. |
| AGENTLATCH-MAN000 | A prompt file referenced by the manifest could not be read | — | Informational coverage note; does not affect `--fail-on`. |

## OWASP category list and coverage report

Category IDs and names are defined once in `src/agent_latch/owasp.py` (`ASI_CATEGORIES`), using the titles from the OWASP publication. A test checks that every rule maps only to those IDs.

Every report includes an ASI01–ASI10 summary: the text and terminal output show a table, JSON has an `owasp_agentic.categories` key, and SARIF has `runs[0].properties.owaspAgenticCoverage`. Each category is shown as one of:

- `N finding(s)`: enabled checks reported findings in this category.
- `no findings from enabled checks`: rules exist for this category but reported nothing. Some only run with a manifest or `--dependencies`, and none fully cover a category.
- `no checks yet`: AgentLatch has no rule for this category (currently ASI06, ASI07, and ASI10).

OWASP category titles and mapping are informational references to the [OWASP Top 10 for Agentic Applications 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/). AgentLatch is independent and is not endorsed, approved, or certified by OWASP. Review the OWASP source for current definitions and version changes.
